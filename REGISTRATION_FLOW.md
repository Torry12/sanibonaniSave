# Group Registration Flow - Complete Implementation Guide

## 🔄 High-Level Registration Flow

```
RegisterGroupScreen (UI)
    ↓ User fills 4-step form
    ↓ vm.submitGroup()
    ├→ GroupViewModel validates all steps
    ├→ Calls groupRepo.createGroup(group, adminEmail, adminPassword)
    ↓
GroupRepositoryImpl.createGroup()
    ├→ Set feeStatus = PENDING_ACTIVATION
    ├→ Create admin user via supabaseManager.signUp()
    ├→ Insert group into Supabase
    ├→ Get created group ID
    ├→ Initialize PlatformFee record (status = DUE)
    ├→ Log warnings if auxiliary records fail (don't fail main flow)
    ├→ Cache in Room: db.groupDao().upsertGroup()
    └→ Return createdGroupId
    ↓
PaymentScreen (YoCo Modal)
    ├→ User pays admin registration fee (R700)
    ├→ On success: groupRepo.activateGroup(groupId)
    └→ Navigate to GroupDashboard
```

## 🔐 Admin User Creation

### **In GroupRepositoryImpl.createGroup()**:

```kotlin
if (adminEmail != null && adminPassword != null) {
    val userId = supabaseManager.signUp(
        email = adminEmail,
        password = adminPassword,
        metadata = mapOf("role" to "group_admin")
    ).getOrThrow()
    
    finalGroup = finalGroup.copy(adminUserId = userId)
}
```

**What Happens in Supabase**:
1. User created in `auth.users` table
2. User ID linked to group via `adminUserId` field
3. Role "group_admin" set in user metadata (for RLS policies)

## 💰 Platform Fee Initialization

### **In GroupRepositoryImpl.createGroup()**:

```kotlin
try {
    val platformFee = PlatformFee(
        id = null,  // Auto-generated by Supabase
        groupId = createdGroupId,
        feeType = "monthly",
        amount = created.currentMembers.toDouble() * 50.0,  // R50 per member
        status = AdminFeeState.DUE  // Initialized as DUE (requires payment)
    )
    supabase.postgrest["platform_fees"].insert(platformFee)
} catch (e: Exception) {
    AppLogger.w("GroupRepository", "Failed to init platform fee: ${e.message}")
    // Continue - don't fail group creation
}
```

**Result**: 
- Platform fee record created with status = "due"
- Amount calculated as `currentMembers * 50` (R50 per member)
- Initially 0 if group starts with 0 members

## 💳 Payment Flow (YoCo Integration)

### **After Step 4 - Submit Button Clicked**:

1. **Validation**: All 4 steps validated
2. **Supabase Operations**:
   - Group created with feeStatus = PENDING_ACTIVATION
   - Admin user created in Auth
   - Platform fee initialized
3. **UI Transition**: 
   - ShowSuccess toast: "Group created! Proceeding to payment..."
   - Navigate to **PaymentScreen** with:
     - `paymentType = "admin_fee"`
     - `amount = 700.0`
     - `groupId = createdGroupId`

### **PaymentScreen**:

```kotlin
@Composable
fun PaymentScreen(
    paymentType: String,      // "admin_fee", "joining_fee", "contribution"
    amount: Double,           // Amount in ZAR
    groupId: String,
    vm: PaymentViewModel = hiltViewModel()
) {
    // Launch YoCo modal
    LaunchedEffect(Unit) {
        vm.launchYocoPayment(amount, paymentType, groupId)
    }
    
    // On successful payment:
    // vm.paymentRepo.recordPayment(payment)
    // vm.groupRepo.activateGroup(groupId)  // Sets registration_paid = true
}
```

### **On Payment Success**:

1. **Call**: `groupRepo.activateGroup(groupId)`
   ```kotlin
   override suspend fun activateGroup(groupId: String): Result<Unit> = runCatching {
       supabase.postgrest["groups"].update(mapOf(
           "registration_paid" to true,
           "fee_status" to AdminFeeState.DUE  // Keep tracking for next month
       )) { filter { eq("id", groupId) } }
       getGroupById(groupId)
       Unit
   }
   ```

2. **Update Group Status**:
   - `registration_paid = true`
   - `feeStatus = DUE` (continues payment tracking)

3. **Navigate to GroupDashboard**

## ⚠️ Error Handling

### **Validation Errors**:
- Displayed as error toast above progress bar
- Users can correct and resubmit
- No data persisted until validation passes

### **Supabase Errors**:
- Network error: Show "Network error. Please try again."
- Auth error: Show "Failed to create admin account"
- Group creation error: Show specific error message
- Auxiliary record failure: Log warning, continue

### **Payment Errors**:
- YoCo modal handles payment failures
- User can retry payment
- Group remains in PENDING_ACTIVATION until payment succeeds
